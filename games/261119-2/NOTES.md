# ぺたっ！おばあちゃんへこづつみ（gf-261119-nx2）

## 起動方法
- `index.html` をそのまま開く（file:// でも Pages のサブフォルダでも可。外部読み込みなし・1ファイル完結）。
- 作り直すとき: `cd tools && npm install && node build.mjs`（`src/*.js` をまとめて `index.html` を出力。実行時ビルドは不要）。

## お話（3場面）
1. つつむ: マフラー・みかん・おえかきを箱へ入れる → ふたを閉じる → テープをびーっ → 宛名とシールをぺたっ → 軽トラの荷台へ。
2. たび: 押している間だけ軽トラが進む。でこぼこ道・もみじ並木（葉が箱にぺたっ）・トンネル・橋 → おばあちゃんの家で箱をおろし、呼び鈴。
3. ひらく: テープをびりびり → ふたをぱかっ → おばあちゃんへ手わたす → 絵を壁にぺたっ → シールをほっぺにぺたっ → 軽トラをタップでもう一度。

## 確認したこと
- 390×844（ヘッドレス Chromium・ソフトウェア描画）で、完成した `index.html` の読み込みと開始時にコンソールエラーなし・外部通信なし。
- お話を1回通して遊んだ: ゲームが出す「次の操作」の手がかり（放置で出る指のお手本と同じ場所・動き）どおりに操作するだけで、つつむ→たび→ひらく→軽トラをタップしてやり直し、まで進めた。エラー 0。
- その1回で各段階の画面を見て、次に触る物が光・動き・構図で示されていることを確かめ、分かりにくかった所を直した（手前のふたが短い動きで閉まらない／宛名のあとシールへ案内がない／絵を持ったまま次の物を受け取る／送り出しで箱が小さい）。

## 既知の問題
- 実機（iPhone / iPad）では未確認。音は耳で確かめていない（合成音のコードが動くことだけ確認）。実機のフレームレートも未計測（下の「描画の軽量化」の仕組みで対応）。
- 横長画面・画面回転・非表示からの復帰は、仕組みは入れたが今回の最小確認では通していない。
- 箱の奥側（むこう半分）に貼ったシールは、おばあちゃんの家でふたを開けるとカメラから見えない。「ほっぺにぺたっ」の案内は手前半分のシールにだけ出る。
- おしまいまで行ったあとに再読み込みすると、最初（つつむ）から始まる。
- 旅のあいだ、荷台の箱はシールが見えるよう 1.45 倍に見せている。
- 画像生成 AI など外部の素材は使っていない（テクスチャ・音はすべて手続き生成）。

## 描画の軽量化（iPhone / iPad 向け）
- 描く画素数の上限: 高精細の倍率は最大 2、さらに描く画素数を約 270 万に抑える（iPad の大画面で重くなりすぎないように。iPhone はほぼそのまま）。
- 動的解像度: フレーム間隔が約 24ms を超えると解像度を 1 割ずつ下げ（最小 0.6）、余裕があれば少しずつ戻す。下げても速くならないとき（省電力モードの 30fps 固定など）は元に戻して、むだに粗くしない。最小まで下げても重いときだけ影を切る。場面切り替え直後と復帰直後は計測しない。
- シェーダーの先読み: 場面に入った直後（画面が隠れている間）に全材質のシェーダーを作る。途中で点け消しするライト（トンネルの灯り・ヘッドライト、玄関の明かり、箱を開けたときの光）は、消えている間は場面から外して1画素ごとの計算を減らし、その組み合わせのシェーダーも先に作っておく。あとから出るもみじの葉・効果の粒も同様。
- たびの木: 道に沿った 30m 区間 × 左右 × 道の近く/遠く ごとにまとめ、画面に入らない組は描かない（見た目は同じ。描く三角形は平均で約 33 万 → 約 15 万）。すすきも遠いときは描かない。
- おばあちゃんの腕の計算で毎フレーム作っていた一時オブジェクトを使い回すようにした。
