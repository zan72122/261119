# ふぉーん！ママのドレッサーでおでかけじゅんび

- **起動**: `index.html` をそのまま開く（単一ファイル・外部読み込みなし。file:// でも Pages の下位フォルダでも動く）。作り直すときは `python3 build.py`（`src/*.js` と `vendor/three.min.js` を1枚にまとめるだけ）。
- **流れ**: 三面鏡を開く → タオルを引く → ドライヤーで乾かす（ふわふわ爆発） → ブラシでとかす（寝ぐせが1本ぴょこん） → オルゴール箱を開ける → クリップで寝ぐせを留める → ポシェットを掛ける → 玄関のドアを開ける → 日傘のママと手をつないでお出かけ → 新しい朝に戻る。
- **確かめたこと**: 390×844 のヘッドレス Chromium（ソフトウェア描画）で、読み込み・開始時にコンソールエラーなし／お話を最初から「新しい朝」に戻るまで1回通し／各段階で「次の1操作」が光・ゆれ・お手本の指で示されること／保存からの再開／WebGL なしで埋め込み画像に切り替わること。
- **未確認・既知の問題**:
  - 音は耳で確かめていない（すべて Web Audio の合成音。笑い声はオカリナ風の音で代用）。
  - 実機（iPhone / iPad の Safari）のタッチ感と実フレームレートは未確認。重いときは解像度を自動で下げ、それでも重いと省電力表示（鏡の解像度・影・髪の本数を減らす）に切り替わる。
  - 通し確認はソフトウェア描画が遅いため、確認用スクリプト側で描画を間引いて進めた（ゲーム本体には手を入れていない）。
  - 髪は毛先がややくし状に見える角度がある。両わきの鏡には女の子は映らない（静止した映り込み）。
  - 掛けたポシェットのひもが体から少し浮く／めり込むことがある。縦長の画面では壁の余白が広め。
  - 保存は localStorage（`gf-261119-1`）。拒否・破損時は保存なしで最初から遊べる。
- **描画パフォーマンス（iPhone / iPad 向け）**:
  - 描画解像度は devicePixelRatio（上限2）に加えて総画素数 約310万の上限をかける。iPhone は従来どおり2倍、大きい iPad は 1.5〜1.7倍程度になる（MSAA はそのまま）。
  - 鏡の反射用レンダーターゲットは、画面上の鏡の大きさ（実ピクセル）に合わせて自動で決める（従来は常に 512×768）。スマホでは描く画素が4割ほど減り、見た目の細かさは画面の画素と同等。
  - シェーダーは起動直後の2〜3フレームでまとめて準備する（鏡用・玄関シーン用・影用を含む）。鏡を開いたときや玄関に切り替えたときの初回コンパイルによるカクつきをなくす。
  - 120Hz 表示（ProMotion の iPad）では1回おきに描いて 60fps に揃える（GPU 負荷と発熱を半分にして、後でスロットリングでガタつくのを防ぐ）。
  - 自動の画質調整は1秒ごとの実フレーム時間で判断し、約42fpsを下回る状態が続くと解像度を1段下げ、3秒続けて滑らかなら1段戻す。直前に失敗した段には戻らない（解像度の上げ下げの往復でカクつかないように）。最下段でも重ければ従来どおり省電力表示に切り替える。
  - ワールド行列の更新は1フレーム1回にまとめた（鏡の描画と本描画で二重に走っていた）。
  - 実機での実測は未確認（ヘッドレス Chromium のソフトウェア描画で、見た目が変わらないこと・エラーがないこと・切り替え時に新しいシェーダーがほぼ作られないことを確認）。
